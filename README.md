# Seer Info｜賽爾號資訊站

《賽爾號》非官方玩家資訊工具，提供精靈、皮膚、刻印、套裝圖鑑，以及競技池、屬性克制查詢、精靈模擬培養、PVE 傷害計算與台服玩家資料查詢。

**網站：** https://seerinfo.app/

> 本站由玩家自行開發與維護，與《賽爾號》官方及遊戲營運方沒有隸屬或合作關係。

## 主要功能

### 首頁與導覽

- 頂部導覽列提供全站搜尋入口，各圖鑑與工具頁面皆可使用
- 電腦版搜尋位於主選單左側，以短分隔線區隔，沿用導覽按鈕風格
- 手機版上排顯示站名與「放大鏡＋搜尋」按鈕，下排導覽等寬排列；管理員選單顯示時也維持等寬
- 圖片輪播採平滑滑動切換，每張停留 7 秒
- 支援上一張／下一張、圖片頁碼、暫停、方向鍵與手機滑動操作
- 配合減少動態效果設定停用切換動畫，並預設暫停自動輪播
- 功能面板分為「圖鑑」與「工具」，提供競技池、屬性克制、模擬培養、傷害計算、玩家查詢與關於本站入口
- 桌面版三個首頁面板維持等寬等高，並提供站長推薦、台服官網公告與更新紀錄
- 上方「工具」選單可開啟競技池、屬性克制、模擬培養、傷害計算與玩家查詢
- 公開功能支援獨立網址分享，可直接開啟對應分頁

### 全站搜尋

- 依名稱或 ID 查詢精靈、皮膚、刻印與套裝，並依工具名稱或常見關鍵字尋找工具入口
- 支援繁簡中文與分類選擇，結果依類別整理，每類圖鑑預覽最多四筆；結果較多時可輸入更完整的名稱縮小範圍
- 圖鑑搜尋資料包含陸服進度，不套用各圖鑑的台服進度篩選
- 送出搜尋後才查詢外部資料，點選結果開啟對應圖鑑或工具
- 搜尋結果顯示於共用視窗，不推動原頁面內容；支援關閉按鈕、Escape 與點擊視窗外側關閉
- 提供載入中、無結果與查詢失敗提示；重新搜尋或清除輸入時，舊查詢不會覆蓋新結果

### 台服玩家資料查詢

從首頁「玩家查詢」或上方「工具 → 玩家查詢」開啟同一個查詢視窗，輸入米米號即可查看：

- 玩家暱稱、在線狀態與在線伺服器
- 離線時的最後登入時間（台灣時間；資料缺失時顯示未知）
- 巔峰競技與巔峰狂野的目前／最高段位、分數與勝率
- 出戰與待戰精靈
- 查詢服務與台服連線狀態

首次開啟查詢視窗時載入查詢程式。需要驗證時可在彈窗內完成；台服連線狀態不代表官方開服狀態。

### 圖鑑

- **精靈圖鑑**
  - 依 ID 或中文名稱搜尋
  - 依單／雙屬性篩選
  - 查看立繪、種族值、技能、魂印與相關資訊
  - 查看關聯皮膚
  - 支援「僅顯示至最新台服進度」

- **皮膚圖鑑**
  - 依 ID、名稱、綁定精靈或皮膚種類搜尋
  - 查看皮膚預覽與對應精靈
  - 支援台服進度篩選

- **刻印圖鑑**
  - 依 ID、名稱、系列、分類與角數篩選
  - 顯示初始、最大、隱藏與最終能力值
  - 支援能力值排序與專屬刻印篩選
  - 支援台服進度篩選
  - 可將目前篩選結果匯出為 Excel

- **套裝圖鑑**
  - 依名稱、效果、PVE／PVP 等條件篩選
  - 查看套裝能力、適用精靈、部件與說明
  - 透過 Ruffle 按需渲染官方 SWF 部件並組裝預覽

### 屬性克制

- 查詢指定屬性的進攻與受擊倍率
- 支援單屬性與雙屬性組合
- 對局屬性助手
- 技能石克制分析

屬性倍率由網站內建資料與計算邏輯完成，不需要額外後端服務。

### 精靈模擬培養

模擬 Lv.100 精靈培養結果，目前是正式功能。

可設定：

- 精靈與關聯皮膚
- 覺醒前／神諭覺醒種族值
- 個性
- 天賦（個體值）
- 學習力
- 三個刻印
- 年費加成
- 戰隊加成
- 套裝
- 目鏡
- 稱號
- 體力上限培養

結果可切換 **基礎／PVE／PVP** 模式，並查看加成來源與計算明細。

培養配置可匯出為 PNG 圖片；支援的瀏覽器也可直接複製圖片到剪貼簿。

也可複製配置分享連結，開啟連結會還原培養設定，並可繼續修改。分享連結包含配置資料，還原時仍需載入對應的遊戲資料。

> 異能精靈、部分特殊套裝例外與戰鬥中的條件效果尚未完整納入。命中、暴擊與減傷不計入六維能力值，模擬結果請以遊戲內實際數值為準。

### PVE 傷害計算

從首頁「傷害計算」、上方「工具 → 傷害計算」或 `?tab=damage` 進入，目前標示為「測試中」。

- 提供「承傷計算」與「傷害計算」兩種模式
- 依序設定屬性、我方資料、BOSS 資料與進階效果，再查看結果
- 支援套裝、常用增減傷效果、攻防範圍比較及最低攻擊／防禦反推
- 選擇我方與 BOSS 屬性後，自動帶入克制倍率，也可手動修改
- 輸入後自動更新計算，各資料框的「重設」只還原該區欄位
- 切換計算模式時回到第一步，保留各模式已填寫的資料；輸入會儲存在目前瀏覽器

採單次攻擊的傷害上下限模型，不處理連擊、機率分布或特殊 BOSS 機制。標題列右側的「計算說明」按鈕可開啟視窗，查看計算前提、結果判讀、效果規則與適用限制。

算法依參考計算器實作，尚未經遊戲實測驗證，並非已驗證的遊戲通用公式。

## 競技池與管理功能

競技池為公開功能，可從首頁「競技池」、上方「工具 → 競技池」或 `?tab=competitive` 查看禁止池、限制池與準限制池。

競技池可切換台服與陸服，兩服共用禁止、限二與限三規則，各自維護期間與名單。
預設台服，分享連結使用 `?tab=competitive&server=tw` 或 `?tab=competitive&server=cn`。
後台建立期間後固定伺服器歸屬；預覽與 CSV 匯出皆標示伺服器。期間統一以 UTC+8 輸入與顯示。
同服期間不可重疊，結束時間可等於下一期開始時間；不同服可同時進行。

部署此功能前，先在 Supabase SQL Editor 執行 `sql/inspect_competitive_pool_servers.sql` 唯讀檢查，
確認同服期間沒有重疊，再執行 `sql/competitive_pool_servers.sql`，最後發布前後台。
Migration 會將既有未標記期間全部歸台服，保留期間 ID 與名單，不複製資料至陸服。
若既有期間重疊，migration 會整筆回滾；需先人工確認期間日期，修正後再執行。
新環境須先建立 `sql/competitive_pools.sql` 及其 `is_admin()` 權限依賴，再執行上述 migration。
兩服皆為公開資料，沿用當期公開讀取及管理員寫入的 RLS，不以服別限制閱讀權限。

賽季與期數使用 `competitive_seasons` 及 `competitive_pools.season_id / pool_number` 管理。
後台直接填寫賽季名稱和數字期數，標題自動顯示為「帝皇賽季 第一池」；未填「賽季」字樣時自動補上。
同服同名賽季自動沿用，不需另外建立或選擇賽季；同一賽季的期數不可重複，兩服的賽季彼此獨立。
修改某個期間的賽季名稱會將該期間改歸到新名稱的賽季，不會改名其他期間。

部署賽季功能前，先確認服別 migration 已完成，再執行 `sql/inspect_competitive_pool_seasons.sql` 檢查拆分結果，
接著執行 `sql/competitive_pool_seasons.sql`，最後發布相符的前後台。
Migration 保留期間 ID、時間與精靈名單，將舊標題拆成賽季和期數；無法辨識的標題或重複期數會使整筆交易回滾。
原 `name` 欄位留存遷移前標題供核對，新功能不再讀寫該欄位。
新增及編輯透過 `save_competitive_pool_period` RPC，在同一交易內建立／沿用賽季並儲存期間，失敗時不留下新賽季。
這個 migration 套用後舊版後台無法建立期間，必須搭配新版程式發布。線上 SQL 與部署須另外執行。

管理員另可使用以下功能：

- `admin.html` 管理競技池期間、精靈名單、批次匯入、預覽與 CSV 匯出。
- 單隻加入可輸入精靈名稱（支援繁簡中文及部分名稱）或 ID；名稱搜尋會列出頭像、名稱與編號，選定確認後再加入。批次匯入仍使用 ID。
- 台服最新精靈、皮膚與刻印進度設定。

一般訪客無須註冊或登入。管理員可從「關於本站 → 站務登入」開啟登入彈窗；驗證管理員身分後，上排才顯示管理選單，提供後台與登出入口。


## 技術

網站以原生 Web 技術為主：

- HTML
- CSS
- JavaScript

- Supabase

- Flatpickr

## 資料來源

主要資料來源：

- [SeerAPI](https://api.seerapi.com/)：精靈、皮膚、刻印、套裝、裝備與其他遊戲資料
- 賽爾號官方資源：精靈圖片、刻印與套裝 SWF 等素材
- [賽爾號 Wiki](https://wiki.biligame.com/seer/)：部分百科資訊、魂印圖片與外部參考
- 網站內建屬性資料：屬性克制計算
- 台服玩家查詢 API：玩家公開資料、巔峰戰績與出戰／待戰精靈；遊戲登入憑證由服務端管理

外部 API、圖片或 SWF 來源無法存取時，對應內容可能暫時無法顯示。

## 本機執行

本專案是靜態網站，但因使用 ES Modules，請透過 HTTP 伺服器開啟，不要直接以 `file://` 執行。

例如使用 Python 3：

```bash
python -m http.server 5500 --bind 127.0.0.1
```

接著開啟：

- 前台：http://127.0.0.1:5500/
- 管理後台：http://127.0.0.1:5500/admin.html

也可以使用 VS Code Live Server 或其他靜態伺服器。

## 測試與檢查

需要 **Node.js 22 或以上版本**。

```bash
npm test
npm run check
```

目前 `package.json` 中：

- `npm test`：使用 Node.js 內建 test runner 執行測試
- `npm run check`：檢查 JavaScript 語法、本地模組引用與循環依賴

另外提供資源完整性檢查：

```bash
node tools/check-assets.mjs
```

測試內容涵蓋屬性倍率、圖鑑 repository、刻印能力與匯出、套裝、模擬培養、圖片處理、伺服器進度設定與部分共用模組契約。

另外涵蓋 PVE 傷害計算、增減傷效果、存活／擊殺判定與最低能力反推，以及玩家資料欄位整理、公開功能導覽與培養配置分享／還原。推送與 Pull Request 會透過 `.github/workflows/ci.yml` 執行測試與模組檢查。

## Supabase

Supabase 用於管理員帳號驗證、競技池資料與台服進度設定。

本站管理功能的相關 SQL 位於 `sql/`，包含：

- 競技池
- 台服進度設定

這些 SQL 主要是現有資料庫功能的建置或更新腳本，**不是完整的新環境初始化方案**。

若要自行部署包含後台功能的版本，除了修改前端 Supabase 專案設定，也必須自行建立正確的資料表、RPC、權限與 RLS 規則。

## 內容維護

- **首頁輪播**：在 `js/app/home-carousel.js` 的 `homeCarouselSlides` 設定圖片、替代文字、響應式來源與裁切位置；圖片放在 `assets/site/`。
- **更新紀錄**：編輯 `data/changelog.json`，每筆包含 `date`（`YYYY-MM-DD`）、`title` 與 `details` 陣列。首頁顯示最新三筆標題，完整紀錄視窗顯示詳細內容。
- **屬性資料**：在 `js/seer-type-data.js` 維護屬性組合與單屬性克制關係；圖標放在 `assets/icons/types/<屬性 ID>.png`。屬性選擇、倍率計算、圖標預載與屬性總數共用這份資料。

## 官網公告自動更新

首頁讀取 `data/official-news.json`，避免瀏覽器跨來源限制。只收錄「○月○日維護與活動更新公告」，日期不固定；找不到符合標題的公告時保留舊版。

- 本機更新：`npm run news:refresh`。
- `.github/workflows/update-official-news.yml` 每小時抓取台服官網，也可在 Actions 手動執行；一般網站發布完成後會再抓取並發布公告，避免公告資料回退。
- 流程驗證公告內容後重新部署靜態網站；抓取失敗會中止部署，線上版本保持原樣。
- 啟用條件：將流程提交到預設分支，並把 GitHub Pages 的 Source 設為 **GitHub Actions**。排程由 GitHub 執行，可能延遲。
- 自動擷取資料只進入 Pages 部署產物，不會自動提交或修改 Git 分支。
