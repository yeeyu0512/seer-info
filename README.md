# Seer Info｜賽爾號資訊站

《賽爾號》非官方玩家資訊工具，整合遊戲圖鑑、培養與傷害計算、競技池及玩家資料查詢，支援繁簡中文搜尋與台服／陸服相關資料。

[前往網站](https://seerinfo.app/) · [更新紀錄](data/changelog.json) · [隱私權政策](https://seerinfo.app/privacy.html)

一般訪客無須註冊或登入。本站由玩家自行開發與維護，與遊戲官方及營運方沒有隸屬或合作關係。

## 功能總覽

| 類別 | 功能 |
| --- | --- |
| 遊戲圖鑑 | 精靈、皮膚、刻印、套裝與異常狀態的搜尋、篩選及詳情 |
| 全站搜尋 | 依名稱、ID 或關鍵字尋找圖鑑資料與工具入口 |
| 屬性克制 | 單／雙屬性倍率、對局屬性助手與技能石分析 |
| 模擬培養 | Lv.100 能力配置、基礎／PVE／PVP 比較、圖片匯出與配置分享 |
| PVE 傷害計算 | 傷害與承傷估算、攻防比較、最低能力反推，目前為測試功能 |
| 競技池 | 台服／陸服當期名單，以及陸服遊戲內票選排名與票數 |
| 玩家查詢 | 台服／陸服玩家資料、巔峰戰績與精靈陣容 |
| 首頁情報 | 台服官網更新公告、網站更新紀錄與功能捷徑 |

寶石圖鑑目前提供預告入口，尚未開放資料查詢。網站支援桌面與手機瀏覽，手機使用專用背景圖片；輪播等動畫配合系統的減少動態效果設定。

### 圖鑑與搜尋

精靈圖鑑可查看立繪、種族值、技能、魂印與關聯皮膚；皮膚圖鑑提供預覽及對應精靈。刻印圖鑑支援能力排序、系列與專屬刻印篩選，並可將篩選結果匯出為 Excel。套裝圖鑑整理能力、適用範圍與部件，透過 Ruffle 載入官方 SWF 組裝預覽。

精靈圖鑑採清單與立繪預覽配置，手機可在預覽與原清單間切換。詳細資料沿用首頁、競技池及票選共用的資訊視窗，提供種族值、魂印與技能段落導覽；從其他入口查看精靈不會改寫圖鑑的搜尋與選取狀態。

名稱搜尋可搭配指定屬性、單／雙屬性及台服進度篩選；更換屬性時保留搜尋文字。屬性按鈕旁的紅色叉號只清除屬性條件，保留台服進度勾選。編號查詢提供全寬預覽，不符合篩選時會顯示原因，調整對應條件後可繼續查看同一編號。

結果列顯示符合條件的總數與已載入數量，可依編號新舊或名稱排序；排序針對完整結果後再分頁，切換排序時保留已選精靈的預覽。

異常狀態圖鑑收錄 45 種狀態，可依名稱、效果或分類查找，詳情提供特殊判定、解除條件及相關狀態連結。尚未確認的資料會保留標示。

精靈、皮膚與刻印圖鑑可選擇僅顯示至最新台服進度。全站搜尋則包含陸服進度，不套用這項篩選；搜尋結果依類別預覽，點選即可開啟對應內容。

### 培養與傷害計算

模擬培養可設定精靈與皮膚、覺醒、個性、天賦、學習力、三個刻印，以及年費、戰隊、套裝、目鏡、稱號與體力培養等加成。結果提供基礎／PVE／PVP 模式與計算明細，可匯出 PNG、在支援的瀏覽器複製圖片，或分享連結還原配置。

PVE 傷害計算提供傷害與承傷兩種模式，可設定屬性、我方與 BOSS 能力、套裝及增減傷效果，查看傷害上下限、攻防比較與最低能力需求。輸入會儲存在目前瀏覽器，完整前提與規則可由頁面的「計算說明」查看。

使用計算工具時請留意：

- 模擬培養尚未完整納入異能精靈、部分特殊套裝與戰鬥條件效果；命中、暴擊與減傷不計入六維能力值。
- 傷害計算採單次攻擊模型，不處理連擊、機率分布或特殊 BOSS 機制；算法依參考計算器實作，尚未經遊戲實測驗證。
- 結果供配置比較與估算，請以遊戲內實際表現為準。

### 競技池與玩家查詢

競技池可切換台服與陸服，查看禁止池、限制池（最多攜帶 2 隻）及準限制池（最多攜帶 3 隻）。進入功能或切換伺服器時預設顯示名單；陸服另可查看限制池前 20 名、準限制池前 30 名的票選排名，點選精靈名稱可開啟資訊。

玩家查詢從首頁或「工具 → 玩家查詢」開啟，輸入米米號即可查看暱稱、在線狀態、最後登入時間、巔峰競技／狂野戰績與出戰／待戰精靈。陸服另提供專家模式分數與勝率；台服需要驗證時可在查詢視窗內完成。服務連線狀態不代表官方開服狀態。

陸服查詢的服務時段與更新方式：

- 玩家查詢與 Bot／票選共用排隊，跨區連線可能需要較長時間。
- 每週三台灣時間 **23:45～23:59** 暫停陸服玩家查詢；票選於該時段每次查詢重新取得票數，以 API 回傳狀態為準。
- 票選一般時段共用後端 5 分鐘快取，僅手動更新；按下更新仍可能取得同一份快取。更新失敗時保留上次成功資料並顯示提示。

## 本機執行

本專案使用 HTML、CSS 與原生 JavaScript ES Modules，沒有前端框架或打包步驟。建議使用 Node.js 22 以上版本，在專案根目錄執行：

```bash
npm run dev
```

啟動前會先同步線上的刻印版本；相同內容的檔案會沿用本機副本。線上版本尚未建立、無法同步或落後最近一次週五台灣時間 18:00，且本機也沒有本週版本時，才從 SeerAPI 產生資料。更新失敗時沿用完整的本機舊檔並提示日期；沒有可用資料時停止，待網路恢復後重試。這項檢查只在啟動時執行，跨過週五 18:00 後請重新啟動。

所有產生的刻印列表與完整資料都放在已忽略的 `tmp/mintmarks/`，不會改寫 Git 追蹤的 `data/`。本機伺服器將 `/data/mintmarks/` 對應到這個暫存目錄。

開啟 [本機前台](http://127.0.0.1:5500/)；後台位於 [admin.html](http://127.0.0.1:5500/admin.html)。如連接埠已被使用，可執行 `npm run dev -- --port 5501`。其他靜態伺服器不會自動同步資料，也不會對應刻印的暫存目錄；本機測試刻印圖鑑請使用 `npm run dev`。

ES Modules 需透過 HTTP 載入，請避免直接以 `file://` 開啟。瀏覽網站不需要 Node.js 或安裝 npm 套件，但圖鑑、玩家查詢、資料庫與 CDN 資源仍需網路連線；本專案只包含網站前端，玩家與票選 API 由外部服務提供。

## 開發與檢查

測試及維護工具使用 **Node.js 22 以上版本**，目前沒有需要安裝的 npm 相依套件。

```bash
npm test
npm run check
node tools/check-assets.mjs
```

| 指令 | 用途 |
| --- | --- |
| `npm test` | 使用 Node.js 內建 test runner 執行測試 |
| `npm run dev` | 自動檢查刻印資料日期，必要時更新後啟動本機網站 |
| `npm run mintmarks:refresh` | 不論資料日期，立即從 SeerAPI 更新 `tmp/mintmarks/` |
| `npm run check` | 檢查 JavaScript 語法、本地模組引用與循環依賴 |
| `node tools/check-assets.mjs` | 依資源清單核對檔案大小與 SHA-256 |
| `npm run news:refresh` | 擷取台服官網更新公告並更新本機 JSON |

測試涵蓋圖鑑資料與搜尋、屬性與培養計算、傷害模型、玩家查詢、競技池、繁簡轉換及分享導覽。推送與 Pull Request 由 [CI](.github/workflows/ci.yml) 執行測試與模組檢查。`tools/` 另有瀏覽器檢查腳本，需另外準備 Playwright 與相符的瀏覽器環境。

## 部署與後台

前端可部署於 GitHub Pages 或其他靜態網站服務。發布內容包含根目錄的 HTML、`assets/`、`css/`、`js/`、`data/`，以及 `favicon.ico`、`robots.txt`、`sitemap.xml`。

更換網域或 repository 子路徑時，請同步檢查 canonical、Open Graph／Twitter metadata、JSON-LD、`robots.txt` 與 `sitemap.xml` 中的網址。

### Supabase 與管理權限

Supabase 負責管理員驗證、競技池資料與台服進度設定。管理員從「關於本站 → 站務登入」登入，通過驗證後可使用後台管理期間與名單、批次匯入、預覽及 CSV 匯出，也可設定台服最新精靈、皮膚與刻印進度。

若自行部署後台，需在 `js/supabase.js` 設定自己的專案，並建立資料表、RPC、管理員判定與 RLS 規則。`sql/` 是現有功能的建置及遷移腳本集合，**不是可直接依序執行的完整初始化方案**。

競技池的伺服器／賽季遷移順序、前後台版本相容性與管理規則，見 [競技池維護與資料庫遷移](docs/competitive-pool-maintenance.md)。玩家查詢及陸服票選的外部服務設定分別位於 `js/player-lookup.js` 與 `js/competitive/votes-api.js`。

### 官網公告自動更新

首頁讀取 `data/official-news.json`，只收錄台服官網的「○月○日維護與活動更新公告」。找不到符合標題的公告時保留舊資料。

[公告更新工作流程](.github/workflows/update-official-news.yml) 在推送至 `main` 後執行，也會每小時執行，並可從 Actions 手動觸發。流程會執行測試、檢查模組、擷取公告，再發布靜態網站；抓取失敗時中止發布，保留線上版本。舊有分支式 Pages 發布完成事件仍保留作為相容入口。

使用此流程需將工作流程放在預設分支，並將 GitHub Pages 的 Source 設為 **GitHub Actions**。排程可能延遲；自動擷取的 JSON 僅寫入部署產物，不會自動提交至 Git 分支。

### 刻印資料自動更新

同一發布流程於每週五台灣時間 **18:00**（UTC `0 10 * * 5`）更新刻印。也可手動執行並勾選 `refresh_mintmarks`。第一次發布時，若線上尚無版本資訊，會自動建立資料。

刻印資料按一般全能、專屬全能、能力、技能分成精簡列表與完整資料。圖鑑預設只下載一般全能列表；其他分類、專屬列表、詳情及匯出資料按需取得。列表已包含最終能力值，搜尋、角數、排序及台服篩選不需額外下載完整資料。模擬培養仍沿用原有資料取得方式。

每次發布先從 `https://seerinfo.app/data/mintmarks/manifest.json` 取得目前線上版本並驗證檔案，放進 `tmp/mintmarks/`；只有週五、指定手動更新或首次建立時才重新抓 SeerAPI。內容相同的資料沿用原本檔名，僅更新檢查日期。新檔案以內容 SHA-256 命名，版本資訊最後寫入；目前與前一版內容會持續隨公告發布沿用，避免短時間內更新造成已開啟頁面拿不到詳情。不累積所有歷史版本；頁面若長期未重整、需要的舊版已移除，須重新整理。

發布時將暫存檔案複製到 `_site/data/mintmarks/`，不提交回 Git，也不使用 Actions cache 作為資料來源。每小時的公告發布會沿用線上刻印版本。線上版本讀取、校驗或來源更新失敗時，整次發布中止，保留原網站；只有版本資訊回應 404 才允許首次建立。若更換網站網域或子路徑，需調整 `tools/mintmark-files.mjs` 的線上來源，發布流程也可透過 `MINTMARK_SOURCE_URL` 指定。

## 資料來源與聲明

- [SeerAPI](https://api.seerapi.com/)：精靈、皮膚、刻印、套裝、裝備與其他遊戲資料。
- 賽爾號官方資源：精靈圖片、刻印、套裝 SWF 等素材；台服官網提供更新公告。
- [賽爾號 Wiki](https://wiki.biligame.com/seer/)：部分百科內容、魂印圖片與外部參考。
- 網站內建資料：屬性克制關係與異常狀態；異常狀態的來源及核實紀錄保留於 JSON。
- 玩家查詢與陸服票選 API：公開玩家資料、戰績、陣容及票選排名；遊戲登入憑證由服務端管理。

外部 API、圖片、CDN 或 SWF 來源無法存取時，相關功能可能暫時不可用。第三方資料及計算結果可能存在遺漏或差異，請配合遊戲內資訊判讀。

《賽爾號》名稱、角色、圖片、SWF、美術素材及其他遊戲相關內容的權利歸原權利人所有。本專案不代表官方立場。
